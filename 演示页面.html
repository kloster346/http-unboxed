⚔️ 灵魂拷问区：GET 和 POST 到底差在哪

点「发送请求」，看两个场景的结果区别。

📮 去快递柜取件GET = 查
URL GET https://api.xxx.com/products?page=1
Body 空（取件不带包裹）
取件码 直接写在地址栏上（?page=1）
⚠️ 明文可见📏 有长度限制♻️ 幂等（取一次不多一个）
✅ 200 —— 快递柜吐出来一份商品清单
{"code":0,"data":{"list":["商品A","商品B","商品C"]}}
🏪 去前台寄件POST = 增/改
URL POST https://api.xxx.com/order
Header Token: xxx（身份证，验明正身）
Body { "user":"张三", "price":99 }
🙈 货物藏在包里📦 能传大体积（图片/长文本）🔁 非幂等（寄一次多一个）
✅ 200 —— 仓库收到并回传「签收单」
{"code":0,"orderId":"o_20250101","msg":"下单成功"}

💡 前端开发 90% 只用 GET 和 POST。剩下 PUT（改全部）/PATCH（改部分）/DELETE（删）是特殊场景，知道概念即可。

🚨 避坑指南：三个高频报错，背下来

先看三张报错卡，再到底下「动手台」亲手踩一遍。

400
请求体/头格式不对
常见因：JSON 多了个逗号、少了个引号
怎么修：检查 Body 里的 JSON 逗号、花括号、引号是否成对
401 / 403
没身份 / 没权限
常见因：Header 里的登录 Token 失效或没带
怎么修：重新登录，拿新 Token 再发
404
找不到这个接口
常见因：URL 路径单词拼错了（order→orde）
怎么修：检查地址栏路径拼写

📋 终极对照表（可拍照/截图带走）

左边是术语，右边是你们公司实际业务的例子。以后跟开发提需求，直接照着说。

术语快递类比业务例子 @ 电商
URL收件地址园区 + 几号楼获取商品列表：GET + URL 参数
Header外露信息寄件人/实名/加急提交订单：带用户 Token（验身份）
Body包裹货物实际货物提交订单：JSON 订单数据
JSON标准化填充物说明书 / 清单订单数据格式 {"user":"张三","price":99}
GET去取件查获取商品列表 / 查订单详情：GET
POST去寄件增/改提交订单：POST + Header( Token ) + Body( JSON )

💡 以后别提「我要调这个接口」，要说「调这个 URL 路径的 POST 接口，Body 里传 JSON 格式的订单数据，Header 里带用户 Token」。开发一听就懂。
